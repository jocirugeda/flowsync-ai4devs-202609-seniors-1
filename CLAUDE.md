# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

FlowSync — a team task-management practice project for the AI4Devs course. Two independent npm
projects, no workspace/monorepo tooling at the root: `backend/` (AdonisJS 7 API) and `frontend/`
(React 19 + Vite). Each has its own `package.json`, `node_modules` and `tsconfig`; always `cd` into
one before running anything.

The current course exercise (described in `README.md`) is about building an agent harness and
comparing output with/without it. Its deliverables are `docs/harness/comparacion.md` (directory does
not exist yet) and `prompts.md` at the root. Course-facing docs in this repo are written in Spanish;
code and code comments are in English.

## Commands

Backend (`cd backend`):

```bash
npm run dev          # node ace serve --hmr  -> http://localhost:3333
npm run test         # runs both Japa suites
npm run lint         # eslint (@adonisjs/eslint-config)
npm run format       # prettier --write . (@adonisjs/prettier-config)
npm run typecheck    # tsc --noEmit
npm run build        # node ace build -> build/

node ace migration:run          # apply migrations AND regenerate database/schema.ts
node ace generate:key           # fills APP_KEY in .env (required on first setup)
node ace list                   # all available generators/commands (make:controller, make:migration, ...)
```

First-time backend setup: `npm install && cp .env.example .env && node ace generate:key && node ace migration:run`.

Running a subset of tests (Japa runner):

```bash
node ace test unit                          # one suite: unit | functional
node ace test --files="users/*"             # by file glob
node ace test --tests="creates a user"      # by exact test title
node ace test --groups="AccessTokens"       # by group name
```

Frontend (`cd frontend`):

```bash
npm run dev      # vite -> http://localhost:5173
npm run build    # tsc -b && vite build
npm run lint     # oxlint (not eslint)
```

There is no test runner configured on the frontend.

## Backend architecture

AdonisJS 7, which differs substantially from AdonisJS 5/6 examples found online. The pieces that
matter and that you cannot infer from a single file:

**Subpath imports, not relative paths.** `package.json#imports` maps `#models/*`, `#controllers/*`,
`#validators/*`, `#transformers/*`, `#generated/*`, `#database/*`, `#start/*`, etc. Import with the
`.js` extension (`import User from '#models/user'`, `import { controllers } from '#generated/controllers'`).

**Generated files — never hand-edit.**
- `database/schema.ts` is generated from the migrations by `node ace migration:run`. Column
  declarations live here, *not* in the model. Adding a field = new migration, then `migration:run`.
- `.adonisjs/server/controllers.ts` is the controller registry consumed by `start/routes.ts`.
- `.adonisjs/client/registry/` is the Tuyau typed-route registry (also used to type the Japa API
  client in `tests/bootstrap.ts`).
Both are regenerated by the `hooks.init` entry in `adonisrc.ts` (`indexEntities` + `generateRegistry`).

**Models compose a generated schema plus mixins.** `app/models/user.ts` is
`compose(UserSchema, withAuthFinder(hash))` — it only adds behaviour (access tokens, the `initials`
getter). Follow that shape for new models.

**Every response is wrapped in `data`.** `providers/api_provider.ts` defines `ApiSerializer`
(`wrap: 'data'`) and attaches `serialize` to every `HttpContext` via module augmentation. Controllers
do `return serialize(...)`; use `serialize.withoutWrapping(...)` for the rare unwrapped case. Output
shape is decided by a transformer in `app/transformers/` (`UserTransformer.transform(user)`), so
never serialize a Lucid model directly into a response.

**Request flow.** `start/kernel.ts` → server middleware (`force_json_response` makes the whole API
JSON-only, container bindings, CORS) → router middleware (bodyparser, session, shield,
initialize_auth, `silent_auth`) → named `middleware.auth()` on protected route groups.

**Routes.** All API routes live in `start/routes.ts` under the `/api/v1` prefix, grouped as
`auth` (public: `POST signup`, `POST login`) and `account` (auth-guarded: `GET profile`,
`POST logout`). Handlers are referenced as `[controllers.Profile, 'show']` from the generated
registry — not by string or direct import.

**Validation.** VineJS 4 with `vine.create(...)` in `app/validators/`, shared rule builders at the
top of the file (`email()`, `password()`), consumed via `request.validateUsing(loginValidator)`.

**Auth.** Default guard is `api` (opaque access tokens in the DB); a `web` session guard is
configured but unused. Login issues `User.accessTokens.create(user)` and returns
`token.value!.release()` once — it is never retrievable again.

**Database.** SQLite via `better-sqlite3`, file at `backend/tmp/db.sqlite3` (gitignored). Postgres/
MySQL/MSSQL/libSQL connections are commented out in `config/database.ts`.

**Tests.** Japa, two suites declared in `adonisrc.ts`: `tests/unit/**/*.spec.ts` (2s timeout) and
`tests/functional/**/*.spec.ts` (30s timeout). Only `tests/bootstrap.ts` exists so far — the API
client, db assertions and auth client plugins are already wired, and API-client routes are typed
from the Tuyau registry.

## Frontend architecture

Still the untouched Vite + React starter: `src/main.tsx` mounts `src/App.tsx`, which is the default
demo page. No router, no state management, no HTTP client, and nothing consumes the backend yet —
any feature work here starts by introducing those. TypeScript runs in project-references mode
(`tsconfig.app.json` for `src/`, `tsconfig.node.json` for the Vite config) with strict-ish flags
(`noUnusedLocals`, `noUnusedParameters`, `verbatimModuleSyntax`, `erasableSyntaxOnly`).

Linting is **oxlint**, configured in `.oxlintrc.json` (react/typescript/oxc plugins) — do not add
ESLint here. There is no Prettier config on the frontend; backend formatting comes from
`@adonisjs/prettier-config` (no semicolons, single quotes, 100 cols).

## Cross-cutting notes

- Backend `.env` is gitignored; `.env.example` is the source of truth for the variable list, and
  `start/env.ts` validates them at boot. CORS allows all origins in dev only (`config/cors.ts`).
- The API is versioned at `/api/v1` and the frontend dev server runs on `:5173`, so browser calls to
  `:3333` are cross-origin — keep that in mind when wiring auth headers.
